# STORAGE AND RECOVERY — SOC SHIFT:30

`src/services/storage.ts`의 원본 명세다.
저장 규칙을 바꾸면 이 문서를 먼저 고친다.

---

## 1. 값 분리

과제 요구사항의 핵심은 **"현재 판은 초기화되고, 보존 대상은 유지된다"** 이다.
그러려면 무엇을 저장하지 *않을지*부터 정해야 한다.

| 구분 | 값 | 새 판 | 새로 접속 | 저장 |
|---|---|---|---|---|
| 현재 판 | 점수, 남은 시간, 라이프, 콤보, 현재 경보 | 초기화 | 복원하지 않음 | **안 함** |
| 개인 기록 | 최고 점수 | 유지 | 유지 | 함 |
| 접근성 | 음소거, 움직임 줄이기 | 유지 | 유지 | 함 |

**현재 판 상태는 어떤 경우에도 저장하지 않는다.**
새로 접속하면 항상 `READY`에서 시작한다. 진행 중이던 판이 복원되면 "다시 시작하면 초기화된다"는 요구를 만족할 수 없다.

## 2. 스키마

```ts
const KEY = 'socshift30:v1';

type Saved = {
  v: 1;
  bestScore: number;      // 정수, 0 이상 999999 이하
  mute: boolean;
  volumeStep: VolumeLevel; // 정수, 0 이상 VOLUME_STEPS 미만
  reduceMotion: boolean;
};

const DEFAULTS: Saved = {
  v: 1,
  bestScore: 0,
  mute: true,        // 첫 로드는 음소거 상태로 시작한다
  volumeStep: 2,     // 5단계 중 가운데. 60%
  reduceMotion: false,
};
```

`mute`의 기본값은 **`true`**다. 브라우저 자동재생 정책에 안전하고, 공개 주소를 처음 여는 사람이 갑자기 소리를 듣지 않는다.
`BUILD_ORDER.md` 8절, `notes/02-game-design.md`의 "첫 로드는 음소거 ON"과 같은 규칙이다.

`reduceMotion`의 기본값은 `false`지만, OS의 `prefers-reduced-motion: reduce`가 켜져 있으면 그 값을 초기값으로 읽는다. 저장된 사용자 설정이 있으면 그것이 우선한다.

- 키에 버전을 넣었다. 스키마가 바뀌면 `socshift30:v2`로 올리고 이전 키는 무시한다.
- `v`가 `1`이 아니면 **전체 기본값**으로 시작한다.
- 알 수 없는 필드는 읽지 않는다.

### 필드를 더할 때는 `v`를 올리지 않는다

`volumeStep`은 나중에 더한 필드다. `v`를 올리면 이전 키를 통째로 버리게 되어
**최고 점수까지 사라진다.** 없는 필드는 기본값으로 채워지므로 버전을 올릴
이유가 없다. 지우는 것과 뜻이 바뀌는 것만 버전 문제다.

### 뜻이 바뀔 때는 이름을 바꾼다

소리 크기는 처음에 `volume`이라는 이름의 3단계(0=LOW 1=MID 2=HIGH)였다.
눈금을 5단계로 늘리면서 **같은 숫자 1이 다른 크기를 뜻하게 됐는데**, 저장된
값만 봐서는 어느 시절 것인지 알 수 없다. 그래서 이름을 `volumeStep`으로 바꿔
**없다는 것 자체를 옛 값이라는 표시로** 쓴다.

읽는 순서는 이렇다.

1. `volumeStep`이 눈금 안의 정수면 그대로 쓴다.
2. 아니면 옛 `volume`을 본다. `0 1 2`는 각각 `0 2 4`로 옮긴다. 가장 작은
   것과 가장 큰 것은 그대로 남는다.
3. 둘 다 없거나 망가졌으면 기본값이다.

한 번 저장하면 `volume`은 사라진다. 통째로 다시 쓰기 때문이다.

## 3. 읽기 규칙

### 필드 단위 복구
한 필드가 깨져도 **그 필드만** 기본값으로 대체하고 나머지는 살린다.
`bestScore`가 문자열이라고 해서 사용자가 설정한 음소거까지 날리지 않는다.

### 검사 순서
1. `localStorage.getItem`을 `try/catch`로 감싼다. 시크릿 모드나 저장소 차단 환경에서 예외가 난다.
2. `null` 또는 빈 문자열이면 기본값 반환.
3. `JSON.parse`를 `try/catch`로 감싼다.
4. 결과가 객체가 아니면(배열, 문자열, `null` 포함) 기본값 반환.
5. `v !== 1`이면 기본값 반환.
6. 필드별로 검증한다.
   - `bestScore`: `typeof === 'number'` **그리고** `Number.isFinite` **그리고** `0 <= n <= 999999`. 아니면 `0`.
   - `mute`, `reduceMotion`: `typeof === 'boolean'`. 아니면 각 필드의 기본값.
   - `volumeStep`: 눈금 안의 정수. 아니면 위의 "뜻이 바뀔 때" 순서를 따른다.

`Number.isFinite`를 반드시 쓴다. `typeof NaN === 'number'`이고 `typeof Infinity === 'number'`라서 타입 검사만으로는 걸러지지 않는다.

---

## 4. 쓰기 규칙

- 저장 시점은 두 곳뿐이다. 한 판이 끝났을 때(최고 점수 갱신 시) / 설정 토글을 눌렀을 때.
- 매 프레임 저장하지 않는다.
- `localStorage.setItem`을 `try/catch`로 감싼다.
- **저장 실패가 게임 실행을 막지 않는다.** 예외를 삼키고 메모리 상태로만 계속 진행한다.
- 저장 실패를 `console.error`로 남기지 않는다. 콘솔 빨간 오류 0건 요구와 충돌한다. 굳이 남긴다면 `console.info`.

## 5. 손상값 복구 검사표

구현 후 아래 8가지를 **실제로 넣어보고** 결과를 기록한다.
브라우저 콘솔에서 값을 심고 새로고침하는 방식으로 검사한다.

```js
localStorage.setItem('socshift30:v1', '<검사값>')
```

| # | 저장 상태 | 심을 값 | 기대 결과 | 실제 결과 | 증거 |
|---|---|---|---|---|---|
| 1 | 저장값 없음 | (키 삭제) | 기본값으로 실행 | 미실행 | |
| 2 | 빈 문자열 | `` | 기본값으로 실행 | 미실행 | |
| 3 | 글자만 있는 값 | `abc` | 기본값으로 실행 | 미실행 | |
| 4 | JSON 문법 오류 | `{"bestScore":` | 기본값으로 실행 | 미실행 | |
| 5 | 필수 항목 누락 | `{}` | 누락 항목만 기본값 | 미실행 | |
| 6 | 잘못된 자료형 | `{"v":1,"bestScore":"높음"}` | 해당 항목만 기본값 | 미실행 | |
| 7 | 음수·과대값 | `{"v":1,"bestScore":-5}` | 허용 범위 기본값 | 미실행 | |
| 8 | 정상값 | `{"v":1,"bestScore":2140,"mute":true,"reduceMotion":false}` | 보존값만 정상 복원 | 미실행 | |

### 추가 경계 검사

| 검사 | 기대 결과 | 실제 결과 |
|---|---|---|
| `{"v":2,"bestScore":9999}` | 버전 불일치 → 전체 기본값 | 미실행 |
| `{"v":1,"bestScore":Infinity}` 상당 값 | `Number.isFinite` 실패 → `0` | 미실행 |
| `[1,2,3]` (배열) | 객체 아님 → 기본값 | 미실행 |
| `null` 문자열 | 객체 아님 → 기본값 | 미실행 |
| 저장소 차단 환경 | 예외를 삼키고 정상 실행 | 미실행 |

**모든 경우에 콘솔 빨간 오류가 0건이어야 한다.** 복구했다는 사실이 오류로 보고되면 안 된다.
