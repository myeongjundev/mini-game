# Game Specification — SOC SHIFT:30

## 1. Core Loop
`Alert → Read → ALLOW/BLOCK → Resolve → Feedback → Next Alert`

## 2. Game Duration
- 기본 제한시간: 30초
- 라이프: 3
- 목표: 30초가 끝날 때까지 라이프가 1 이상

## 3. Controls
- Keyboard
  - `A` or `←`: ALLOW
  - `D` or `→`: BLOCK
  - `P` or `Esc`: Pause/Resume
- Mouse
  - ALLOW button
  - BLOCK button
  - Pause button

핵심 조건:
**한 번의 사용자 입력은 정확히 한 번만 판정되어야 한다.**

## 4. Alert Model
각 Alert는 최소 다음 속성을 가진다.

```ts
type Alert = {
  id: string;
  category: "traffic" | "login" | "scan" | "dns" | "critical";
  title: string;
  facts: { label: string; value: string; signal: "normal" | "suspicious" }[];
  correctAction: "ALLOW" | "BLOCK";
  severity: "LOW" | "MEDIUM" | "HIGH" | "CRITICAL";
  explanation: string;
};
```

`correctAction`은 프론트에 그대로 노출하지 않는다.

## 5. 판정
### Correct
- 정상 이벤트 + ALLOW
- 위협 이벤트 + BLOCK

### False Positive
- 정상 이벤트 + BLOCK

### Missed Threat
- 위협 이벤트 + ALLOW

### Timeout / No Decision
- `eventIntervalMs` 안에 판단하지 않음
- 라이프 -1, 콤보 0, 점수 +0
- `reviewed`, 오탐·미탐 및 정상 처리 통계에는 포함하지 않고 `timeouts`로 별도 집계

## 6. 점수 예시
초기 구현은 단순해야 한다.

- Correct: +100
- Critical Correct: +300
- Wrong: +0
- 3연속 이상 Correct부터 combo bonus 적용 가능

점수 공식이 복잡해지면 문서부터 갱신한다.

## 7. Life
- 오답: -1
- 미판정 경보(`TIMEOUT`): -1
- MVP에서는 Critical 오답도 -1로 시작한다.
- 테스트 후 필요 시 변경하되 데이터 근거를 남긴다.

## 8. Difficulty
### 0–10초
명확한 이벤트 위주.

### 10–20초
정보량 또는 등장 속도를 약간 증가.

### 20–30초
고위험 이벤트 비중 증가.

중요:
과제용 난이도 실험에서는 **상수 하나만 바꾼다.**
권장 실험 변수: `eventIntervalMs`

## 9. State Machine
```text
READY
  ↓ start
PLAYING
  ├─ pause → PAUSED
  │            ├─ resume → PLAYING
  │            └─ restart → READY
  ├─ life == 0 → FAILURE
  └─ time == 0 → SUCCESS

SUCCESS / FAILURE
  ↓ restart
READY
```

## 13. MEMO — 근무 중 방해

새벽 근무 중 사내에서 올라오는 공지 한 줄이다. **주의를 나누게 만드는 것**이
목적이고, 동시에 뒤에 올 경보의 판단 근거를 준다.

### 13.1 왜 넣는가

지금 게임에는 "주의 분산"이 없다. 실제 SOC 야간 근무는 경보를 보는 중에
메신저가 울리고 전화가 온다. 그것이 이 직무의 핵심 난이도다.

다만 방해가 **순수한 비용**이면 짜증만 남는다. 그래서 메모는 정보를 함께
준다. 읽으면 뒤에 올 경보를 자신 있게 판정할 수 있다.

### 13.2 핵심 규칙

**메모가 떠 있는 동안 `A` / `D` 판정 입력이 막히고, 현재 경보의 제한시간도
함께 멈춘다. 30초 근무 시계는 계속 흐른다.**

경보 한 장의 수명은 `eventIntervalMs`, 즉 3초다. 메모를 읽고 닫는 데 그 상당 부분
이상이 들고, 읽는 동안은 경보를 볼 수도 없다. 경보 제한시간을 멈추지 않으면 메모가 뜬 경보는 실력과 무관하게
미판정이 되고, 이는 13.3의 공정성 규칙을 정면으로 어긴다. 13.10에서 비밀번호
연타를 뺀 것과 **같은 계산**이다.

비용은 근무 시계 쪽에서 받는다. 메모를 오래 열어두면 그만큼 30초 안에 처리할
경보가 줄어든다.

| 선택 | 얻는 것 | 잃는 것 |
|---|---|---|
| 바로 닫는다 | 근무 시간 | 지금 당장의 근거 (로그에는 남는다) |
| 읽고 닫는다 | 뒤에 올 경보의 근거를 머리에 넣는다 | 근무 시간 0.5~1초 |

빨리 닫으면 비용이 거의 0이다. **벌이 아니라 선택이어야 한다.** 비용의
상한을 플레이어가 정한다.

**13.6-1의 로그가 생기면서 "바로 닫으면 정보를 잃는다"는 더 이상 사실이
아니다.** 대신 *언제 읽을지*를 고르는 문제가 된다. 지금 읽으면 근무 시간을
쓰고, 나중에 읽으면 그때 시선을 옮겨야 한다. 정보 자체는 잃지 않는다.

이 교환을 약하게 만드는 변경인 줄 알고 넣었다. **기억에 의존하게 두는
쪽이 더 나쁘다고 봤다.** 근거는 13.6-1에 있다.

### 13.2-1 놓이는 자리

**메모는 경보 카드를 덮는다.** 판정 버튼은 사라지지 않고 비활성으로 자리를
지킨다.

- 시선이 이미 경보 카드에 있다. 화면 아래에 띄우면 눈에 들어오지 않는다
- 화면 아래는 판정 표시(`.verdict-flash`)의 자리다. 겹치면 둘 다 못 읽는다
- 겹쳐 놓으므로 화면 높이가 늘지 않는다. 1366×768에서 세로 넘침이 없다
- 카드를 가려도 손해가 없다. 그 동안 경보 제한시간이 멈춰 있기 때문이다
- 버튼을 지우면 "눌렀는데 왜 안 되지"가 아니라 "버튼이 어디 갔지"가 된다.
  비활성 버튼은 막혔다는 사실 자체를 화면에 남긴다

### 13.3 공정성 규칙

- **메모가 떠 있는 동안 현재 경보의 제한시간은 멈춘다.** 이것이 공정성의
  본체다. 등장 시점만 맞추고 시계를 계속 돌리면 미판정을 피할 방법이 없다
- **메모는 새 경보가 뜬 직후에만 나타난다.** 슬롯 시각은 발화 시점이 아니라
  자격 시점이다. 판을 끝낸 뒤 메모가 홀로 남는 일도 이걸로 막는다
- 메모를 놓쳐도 **벌은 없다.** 근무 시간을 뺏는 것만으로 충분한 비용이다
- 일시정지 중에는 메모도 멈춘다. 경과 시간 기준으로 동작하므로 자동으로 지켜진다

### 13.4 메모와 경보 짝짓기

큐는 티어별 봉지다. 한 봉지를 다 뽑기 전에는 반복되지 않으므로, **그 티어의
경보는 해당 구간에 반드시 나온다.** 따라서 메모를 연결된 경보의 티어가
시작되기 전에 띄우면 짝이 자동으로 맞는다. 큐를 따로 손대지 않는다.

| 메모 | 연결 경보 | 티어 | 그 경보의 정답 |
|---|---|---|---|
| 판촉 행사, 트래픽 3배 예상 — 마케팅팀 | `traffic-spike` | 2 | ALLOW |
| employee_07 신규 노트북 지급 완료 — IT팀 | `known-user-new-device` | 2 | ALLOW |
| 신규 도메인 등록 요청 없음 — 보안팀 | `dns-tunnel` | 2 | BLOCK |
| 02:00 정기 백업 시작 예정 — 인프라팀 | `backup-job` | 3 | ALLOW |
| 계약직 권한에 운영 DB 제외 — 보안팀 | `contractor-proddb` | 3 | BLOCK |
| intern_03 온보딩 중, 권한 변경 요청 없음 — 인사팀 | `priv-esc` | 3 | BLOCK |

**정답이 ALLOW인 것 3개, BLOCK인 것 3개다.** 이 균형을 깨면 안 된다.
전부 ALLOW를 도우면 "메모를 봤으면 통과"라는 새 정답표가 생긴다.
심각도를 카드에서 제거한 것과 같은 이유다.

### 13.5 등장 시각

한 판에 **4개**. 슬롯은 경과 시간 기준으로 고정한다.

| 슬롯 | 경과 | 뽑는 곳 |
|---|---|---|
| 1 | 3초 | 티어 2 연결 메모 3개 중 |
| 2 | 7초 | 티어 2 연결 메모 (1과 중복 없음) |
| 3 | 12초 | 티어 3 연결 메모 3개 중 |
| 4 | 16초 | 티어 3 연결 메모 (3과 중복 없음) |

슬롯이 시간 기준이므로 `eventIntervalMs`를 바꿔도 메모 배치는 그대로다.
난이도 실험에서 변수가 섞이지 않는다.

선택은 경보 큐와 **같은 시드 난수**를 쓴다. 테스트에서 결정적으로 검증된다.

### 13.6 결과 화면

`MEMOS READ 2 / 4` 한 줄을 추가한다. 화면에 **0.6초 이상** 떠 있다가 닫히면
읽은 것으로 센다. 점수나 등급에는 반영하지 않는다.

13.6-1의 로그가 생긴 뒤로 이 값은 **정보를 얻었는지가 아니라 근무 중에
멈춰 서서 읽었는지**를 센다. 로그에 남으므로 바로 닫아도 내용은 볼 수 있다.

### 13.6-1 메모 로그

닫은 메모를 모아 둔다. 근무 내내 볼 수 있다.

**왜 넣는가.** 메모는 닫으면 사라지는데 연결 경보는 그 티어가 시작된 뒤에
온다. 슬롯 1(3초)이 가리키는 경보는 10~20초 구간이라 **최대 17초를 기억하고
있어야 했고 다시 볼 방법이 없었다.** 그 사이 경보 일고여덟 장을 판정한다.
기억하지 못하면 메모는 근무 시간만 뺏고 정보는 못 주는 것이 된다.

시간 압박을 거는 게임은 기억력까지 함께 시험하지 않는 편이다. Papers,
Please는 규칙집을 판정 도중에 언제든 펼칠 수 있고, 오버쿡드는 주문표가
화면에 계속 떠 있다. 압박이 두 겹이면 억울해진다.

**무엇을 남기는가.** 뜬 메모는 전부, 내용까지 남긴다. 읽었는지는 따지지
않는다. 읽은 것만 남기는 안도 검토했으나(13.2의 교환이 그대로 살아난다)
규칙이 하나 늘어나는 값을 하지 못한다고 봤다.

**어디에 두는가.**

| 화면 | 자리 |
|---|---|
| 1320px 이상 | 셸 오른쪽 바깥. 절대 위치라 본편 레이아웃이 그대로다 |
| 1320px 미만 | 판정 버튼 아래. 목록 높이를 104px로 묶고 안에서만 굴린다 |

경계는 셸이 가운데 있다는 데서 나온다. 한쪽 여백이 `(V - 48 - 720) / 2`라
패널 240px과 간격 24px이 들어가려면 `V >= 1296`이어야 한다. 1320px으로
잡아 여유를 뒀다.

좁은 화면에서 높이를 묶는 이유는 **본편 화면이 로그 없이도 이미 빠듯하기
때문이다.** 390×844에서 44px, 1280×720에서 19px 넘친다. 넉 장을 다 펼치면
274px이 더 붙는데, 묶으면 165px이고 판정 버튼은 스크롤 없이 보인다.

**판이 시작될 때부터 자리를 지킨다.** 첫 메모가 뜨는 3초에 갑자기 나타나면
그때 화면이 밀리고, 여기 쌓인다는 것도 알 수 없다.

**결과 화면에서는 두 군데에 나온다.**

- **판정 기록 안** — 그 경보를 돕던 공지를 항목 밑에 붙인다. 짝은 13.4에
  있고 `Memo.alertId`와 `DecisionRecord.alertId`로 잇는다. 틀린 경보 밑에
  붙으면 "그 정보를 갖고 있었다"가 드러난다. 다음 판에 공지를 읽게 만드는
  가장 강한 장치다
- **오른쪽 목록** — 받은 공지 전부. 근무 중과 같은 자리다

목록만 두면 어느 공지가 어느 경보용이었는지 사람이 맞춰봐야 한다. 항목에만
붙이면 경보가 나오지 않은 공지가 사라진다. 그래서 둘 다 둔다.

**경보가 끝내 나오지 않은 공지는 그렇게 적는다.** 슬롯 3·4는 티어 3 경보를
돕는데 티어 3은 20초부터다. 20초를 못 넘기고 끝나면 그 두 장은 가리킬
경보가 없었던 셈이고, 네 장을 다 읽느라 근무 시간을 썼는데 절반은 쓸 데가
없었던 것이 된다. 실제로 19.4초에 끝난 판에서 `MEMOS READ 4 / 4`가 나왔다.

**규칙은 아직 바꾸지 않는다.** 슬롯 시각을 앞으로 당기면 기억 거리가 다시
멀어지고, 무엇보다 난이도 실험 중에는 규칙을 고정해야 한다. 결과 화면에
표시만 해두고 20판에서 얼마나 자주 그러는지 본 뒤 정한다.

### 13.7 입력

| 키 | 동작 |
|---|---|
| `SPACE` 또는 클릭 | 메모 닫기 |
| `A` / `D` / `←` / `→` | **무시된다.** 눈 감고 판정하는 사고를 막는다 |
| `P` / `ESC` | 일시정지. 평소와 같다 |

### 13.8 접근성

- 메모 등장을 라이브 리전으로 알린다
- Reduce Motion이면 슬라이드 없이 즉시 표시한다
- 글자 11px 하한을 지킨다
- 도트 아이콘은 흑백에서도 구별되어야 한다 (`PIXEL_ICONS.md` 검수 기준)

### 13.9 상수

`config.ts`에 모은다. **난이도 실험 중에는 이 값을 고정한다.**

```ts
export const MEMO = {
  perShift: 4,
  slotsMs: [3_000, 7_000, 12_000, 16_000],
  readThresholdMs: 600,
} as const
```

### 13.10 이번 범위 밖

`AI_DECISION_LOG`에 남길 판단이다. 방해 요소로 함께 논의했으나 1단계에
넣지 않는다.

- ~~**상사의 전화**~~ — **14절로 옮겼다.** 받는 시간을 넘기면 라이프를
  잃는 규칙이 정해지면서 명세할 것이 생겼다. 구현은 난이도 실험 뒤다
- **비밀번호 연타 입력** — 5회 연타는 경보 한 장 창(3초)의 3분의 1을 먹어
  피할 수 없는 라이프 손실이 된다. 넣는다면 경보 한 장 자리를 대신 차지하는
  형태여야 한다. `event.repeat` 가드와도 규칙이 충돌한다

한꺼번에 넣으면 무엇이 재미있고 무엇이 짜증나는지 구분할 수 없다.
메모를 먼저 넣고 반응을 본 뒤 결정한다.

## 14. PHONE — 상사의 전화

13.10에서 미뤄뒀던 방해 요소다. 화면 상태와 자산은
`prompts/03_PHONE_PASSWORD_DISTRACTIONS_HANDOFF.md` 3절에 있다.

### 14.1 이 요소만 할 수 있는 일

**지금 이 게임의 정보는 전부 협조적이다.** 카드는 사실을 주고 메모는 근거를
준다. 어떤 요소도 플레이어를 틀리게 만들지 않는다. 메모는 플레이어를
**더 맞게만** 만든다.

전화는 **틀리게 만들 수 있는 유일한 요소다.**

그리고 그것이 이 직무의 진짜 난이도다. 실제 관제에서 가장 어려운 순간은
기술이 아니라 사람이다. 권한 있는 사람이 "그거 통과시켜"라고 말할 때다.
`AI_DECISION_LOG` 001에서 네트워크 퀴즈와 차별화하려고 SOC 판단 구조를
골랐는데, **퀴즈가 할 수 없는 것이 이것이다.**

### 14.2 두 층으로 나눈다

| 층 | 성격 | 설계 |
|---|---|---|
| 받기 | **세금** | 강제다. `ringMs` 안에 안 받으면 라이프 -1 |
| 통화 | **게임** | 상사의 지시를 따를지 정한다 |
| 결과 | 기존 경로 | 따르고 틀리면 오답으로 라이프 -1 |

**받는 것 자체를 선택으로 두지 않는 이유.** 안 받는 값이 라이프 1개(전체
버퍼의 33%)면 최적 플레이는 언제나 즉시 받기로 굳는다. 그러면 `↓ 나중에`는
아는 사람은 절대 누르지 않는, **초보만 벌하는 선택지**가 된다.
비용에 지배 전략이 있으면 그것은 선택이 아니라 세금이다.

세금인 것이 나쁘지 않다. 설명이 필요 없고, 방해에 이빨이 생긴다.
**대신 진짜 딜레마를 통화 내용으로 올린다.**

**새 실패 경로를 만들지 않는다.** 지시를 따라 틀리면 기존 오답 처리로
라이프를 잃는다. 라이프를 잃는 방법은 여전히 판정 하나뿐이다.

### 14.3 받기 규칙

**전화는 `PHONE.ringMs` 동안 울린다. 그 안에 받지 않으면 라이프 -1, 콤보 0.**

- `↑`로 받으면 통화로 넘어가고 벨 시계가 멈춘다
- `↓ 나중에`는 **팝업만 내린다. 벨 시계는 계속 간다.** 화면 구석에 울리는
  중임을 남긴다. 그동안 경보는 정상으로 판정할 수 있다
- 벨이 다 가면 `reviewed`는 올리지 않는다. 경보를 검토한 것이 아니므로
  Accuracy를 오염시키면 안 된다. `TIMEOUT`과 별도로 집계한다
- 통화 중에는 `↓`로 끊는다

`↓ 나중에`는 최적 플레이가 아니지만 남긴다. 경보를 판정하던 손을 멈추지
않고 몇 초를 벌 수 있고, 13.10이 전화를 고른 이유("무시할 수 있게 하고
점점 거슬리게")의 마지막 조각이다.

### 14.4 통화 — 여기가 게임이다

**상사는 다음에 뽑힐 티어 3 경보 하나를 지목하고 처리 방법을 지시한다.**

지시는 두 가지뿐이다.

| 지시 | 그 경보의 정답이 ALLOW면 | BLOCK이면 |
|---|---|---|
| "통과시켜" | **참** | **거짓** — 따르면 미탐 |
| "막아" | **거짓** — 따르면 오탐 | **참** |

거짓 지시가 결과 화면의 **오탐·미탐 2축 어느 쪽으로도** 갈 수 있다.
BLOCK 버튼을 앰버로 둔 이유(차단이 공짜가 아니다)와 같은 축이다.

#### 지배 전략을 없애는 규칙 둘

**하나. 참인 지시는 카드만으로는 확신할 수 없는 것을 확인해준다.**
**둘. 거짓인 지시는 그 카드에 반드시 반증이 있다.**

반증 없는 거짓을 넣으면 대조할 것이 없어 찍기가 된다. **심각도 93%,
표시 개수 93%와 같은 계열의 실수다.** 정답이 카드 밖에서 정해지면 안 된다.

이 둘이 있어야 스킬이 생긴다. **상사의 말과 카드를 대조한다.** 이 게임의
핵심 스킬(행위가 아니라 자격을 본다)을 사람에게 적용한 것이다.

#### 데이터가 이미 이 짝을 갖고 있다

| 경보 | 카드가 보여주는 것 | 지시 | 참·거짓 | 대조할 근거 |
|---|---|---|---|---|
| `backup-job` (ALLOW) | 6.1 GB, 02:00 — **무섭게 생겼다** | "통과시켜" | 참 | 목적지가 Registered Backup Server |
| `contractor-proddb` (BLOCK) | MFA Pass — **정상처럼 보인다** | "통과시켜" | 거짓 | HISTORY: First Access, RESOURCE: Production DB |

가이드 3쪽이 가르치는 `exfil` / `backup-job` 쌍과 **같은 구조**다.
전화는 그 교훈의 사람 버전이다.

#### 참·거짓 비율은 1 : 1

한 판에 한 번뿐이라 판마다 바뀐다. 어느 쪽으로 기울면 "항상 따른다" 또는
"항상 무시한다"가 정답표가 된다. **메모의 ALLOW 3 / BLOCK 3과 같은 이유다.**

#### 큐를 건드리지 않고 비율을 지키는 법

경보 큐는 티어별 봉지이고 13.4에서 **큐를 따로 손대지 않는다**고 정했다.
전화가 특정 경보를 지목하려고 큐를 바꾸면 그 약속이 깨진다.

그래서 **뽑지 않고 들여다본다.** `remainingByTier[3]`의 맨 앞이 다음에 나올
티어 3 경보다. 그것을 읽고, 시드 난수로 지시를 고른다.

- 정답과 **같은** 지시를 고르면 참
- 정답과 **다른** 지시를 고르면 거짓

봉지 순서와 무관하게 1 : 1이 유지된다. 큐는 읽기만 하고 바뀌지 않는다.

**정답 방향으로 지시를 정하지 않는다.** 티어 3은 BLOCK 4 / ALLOW 1이라
"통과시켜"를 고정하면 지시의 80%가 거짓이 된다.

#### 한 경보에 출처는 하나

**한 경보에 메모와 통화가 함께 붙지 않는다.** 겹치면 전화가 알려줄 것이
없어지고, 받을 이유도 사라진다.

**구현은 메모가 아니라 전화 쪽에서 피한다.** 메모는 3~18초에 이미 다
발화하고 전화는 21초라, "지목한 경보의 메모를 띄우지 않는다"는 순서로는
될 수 없다. 그래서 지목할 때 **이번 판에 공지가 뜬 경보를 건너뛴다.**
결과는 같다 — 한 경보에 출처는 하나다.

건너뛰어도 지목할 것은 남는다. 티어 3 경보 5장 중 공지가 붙는 것은
`backup-job`·`contractor-proddb`·`priv-esc` 셋이고, 한 판에 뜨는 티어 3
공지는 슬롯 2개뿐이다.

메모를 반증으로 겹쳐 두는 안(공지를 읽었으면 상사의 거짓말을 바로 안다)도
검토했다. 그 순간의 맛은 좋지만 **메모가 뽑히느냐에 기대는 설계**이고,
준비된 플레이어에게 거짓말이 너무 쉽게 들통나 딜레마가 약해진다.

### 14.5 공정성 규칙

라이프를 잃는 경로가 늘어나는 변경이므로 13.3보다 엄격하게 본다.
이 저장소는 "실력으로 피할 수 없는 라이프 손실"을 두 번 걷어냈다.
비밀번호 연타(13.10)와 메모가 뜬 경보의 미판정(13.2)이다.

- **팝업이 떠 있는 동안 현재 경보의 제한시간은 멈춘다.** 13.3과 같다.
  전화 때문에 경보까지 놓치면 방해 한 번에 라이프를 둘 잃는다
- **`↓ 나중에`를 누르면 경보 제한시간이 다시 흐른다.** 미루는 대신 경보를
  처리할 수 있어야 미루는 선택에 값이 생긴다
- **메모와 전화는 같은 시각에 뜨지 않는다.** 둘 다 판정을 막으므로 겹치면
  경보를 볼 수 없는 구간이 생긴다. 슬롯 계산은 14.7에 있다
- **벨이 근무 종료 전에 끝나야 한다.** 30초에 걸치면 손쓸 수 없는 손실이 된다
- 일시정지 중에는 벨 시계도 멈춘다
- **일시정지 중에는 전화를 조작할 수 없다.** 벨 시계가 멈춘 채로 받을 수
  있으면 일시정지가 이득이 된다 — 라이프를 잃을 위험 없이 상사의 말을 읽고
  대조할 시간을 번다. 공정성이 한쪽으로만 기울면 안 된다. 메모 닫기도
  같다(13절). 리듀서가 `phase !== 'PLAYING'`에서 거절하고, 화면도 근무
  중일 때만 키를 넘긴다

### 14.6 입력

`prompts/03` 3.2절 표를 따른다.

| 상태 | `↑` | `↓` | `←` `→` `A` `D` |
|---|---|---|---|
| 수신 팝업 | 받기 | 나중에 | 판정 차단 |
| 통화 중 | 없음 | 통화 종료 | 판정 차단 |
| 나중에로 내림 | 받기 | 없음 | **정상 판정** |

`event.repeat` 가드를 그대로 쓴다. `P`·`ESC` 일시정지는 기존 규칙대로다.

**`↑`·`↓`는 지금 게임에서 쓰지 않는 키다.** `←`·`→`가 판정에 묶여 있으므로
전화에 좌우를 쓰면 판정과 충돌한다.

### 14.7 상수

| 상수 | 제안 | 근거 |
|---|---|---|
| `PHONE.perShift` | 1 | 난이도 실험에 변수를 더 얹지 않는다 |
| `PHONE.slotMs` | 21_000 | 아래 계산 |
| `PHONE.ringMs` | 6_000 | 경보 두 장 분량. 미루고 한 장 처리한 뒤 받을 수 있다 |

**`config.ts`의 `PHONE`에 들어 있다. 난이도 실험 중에는 고정한다.**

`eventIntervalMs`가 3000이므로 경보는 0·3·6·9·12·15·18·21·24·27초에 뜬다.
메모 슬롯(3·7·12·16초)은 자격 시각이라 실제로는 **3·9·12·18초**에 발화한다.

21초는 메모 넷 어디와도 겹치지 않고, 벨 6초가 27초에 끝나 근무 종료 3초
전에 결판난다. 티어 3 구간이라 지목할 경보가 봉지에 남아 있다.

**24초는 쓸 수 없다.** 벨이 30초를 넘겨 근무 종료와 동시에 라이프가 깎인다.
14.5를 어긴다.

### 14.8 결과 화면

판정 기록에서 그 경보 항목에 상사의 지시와 플레이어의 선택을 함께 붙인다.
메모 로그(13.6-1)가 판정 기록에 공지를 붙이는 것과 같은 장치다.

```text
UNAUTHORIZED RESOURCE ACCESS      MISSED THREAT
지시 "통과시켜"  ·  ORDER FOLLOWED
```

**틀린 경보 밑에 "상사 말을 따랐다"가 드러나는 것이 이 장치의 전부다.**
다음 판에 대조하게 만드는 가장 강한 순간이다.

**받지 않은 전화의 지시는 붙이지 않는다.** 안 들은 말을 "따랐다"고 적으면
우연히 같은 선택을 한 것이 복종으로 기록된다. 이 장치는 상사의 말과 카드가
부딪히는 순간을 보여주는 것인데, 못 들었으면 부딪힌 적이 없다. 판정 시점에
`phoneAnswered > 0`인지로 가른다. 인수인계서(15.3)도 같은 규칙을 쓴다 —
한 화면에서 두 곳이 다른 말을 하면 안 된다.

지목한 경보가 끝내 나오지 않은 판도 있다. 티어 3 구간이 10초인데 3000ms면
3.3장만 뽑히므로 5장 중 일부는 안 나온다. 13.6-1의 공지 처리와 같이
**"그 경보는 나오기 전에 근무가 끝났습니다"로 적는다.**

### 14.9 아직 정하지 않은 것

- **`ringMs` 6초가 맞는지.** 받는 데 필요한 것은 키 하나지만, 경보를
  판정하던 주의를 돌리는 값이 얼마인지는 재봐야 안다. **손으로 확인할 것**
- 통화 문장의 말투와 길이. 한 번에 표시하고 타자기 효과는 쓰지 않는다.
  대사는 `data/phoneCalls.ts`에 티어 3 경보 5장 × 지시 2종으로 있다
- 지시를 거절했을 때 상사 쪽 반응을 남길지. 지금 규칙에는 없다
- 무시한 전화의 재수신. **지금 규칙에는 없다.** 한 번 울리고 끝난다

### 14.10 버린 안

| 안 | 버린 이유 |
|---|---|
| 메모처럼 정보만 주고 벌 없음 | 메모에 껍데기만 씌운 것이 된다. 차별화가 없다 |
| 안 받으면 다음 경보의 사실 한 줄이 `NO DATA` | 우아하지만 30초 안에서 눈에 띄지 않는다 |
| 안 받으면 콤보만 끊김 | 너무 약해서 무시된다. 방해에 이빨이 없다 |
| 상사가 항상 "통과시켜" | 티어 3이 BLOCK 4 / ALLOW 1이라 지시의 80%가 거짓이 된다 |
| 전화가 지목할 경보를 큐에서 당겨오기 | 13.4의 "큐를 따로 손대지 않는다"를 깬다 |

### 14.11 구현 시점 — 완료 (2026-08-20)

**난이도 실험 20판을 시작하기 전에 넣었다.**

이 절에는 원래 "실험이 끝난 뒤"라고 적혀 있었고, 이유로 "라이프를 잃는
경로가 늘면 실험 기준값이 무효가 된다"를 들었다. **그 논리는 틀렸다.**
무효가 되는 것은 *실험 도중에* 규칙을 바꿀 때다. 아직 한 판도 기록하지
않았으므로, 전화를 넣고 규칙을 통째로 얼린 뒤 20판을 돌리면 앞뒤 10판
모두 전화가 켜져 있어 비교 조건이 같다. 움직이는 값은 여전히
`eventIntervalMs` 하나다.

지켜야 하는 순서는 이것뿐이다.

> **실험 전에 넣기는 된다. 실험 중에 넣기는 안 된다.**

대신 실제로 감수한 것이 둘 있다.

- **판마다 편차가 커진다.** 벨을 놓치면 라이프 3개 중 1개가 날아가고,
  거짓 지시를 따르면 오답이 하나 는다. 10판씩으로는 `eventIntervalMs`
  차이가 잡음에 묻힐 수 있다
- **실험 시작 뒤에 버그가 나오면 앞 기록이 날아간다.** 그래서 손 확인을
  먼저 끝내고 규칙을 얼린다

## 15. HANDOVER — 인수인계서

결과 화면 맨 위에 얹는 **다음 근무자에게 넘기는 문서**다. 게임의 내용은
새벽 2시의 노동인데 결과 화면만 `SCORE` / `MAX COMBO`라 어긋나 있었다.
같은 판을 사람 말로 다시 쓴다.

구현은 `src/game/engine/handover.ts`와 `src/components/HandoverReport.tsx`.

### 15.1 표시 레이어다

**규칙을 하나도 건드리지 않는다.** 점수·라이프·경보 큐·전화·메모 어디에도
값을 쓰지 않고, 근무가 끝난 뒤 이미 쌓인 상태만 읽어 문장으로 바꾼다.

읽는 값은 `log` · `phoneLog` · `phoneMissed` · `timeouts` ·
`missedThreats` · `falsePositives` · `timeLeftMs` · `phase`뿐이다.

그래서 **난이도 실험의 통제 대상이 아니다.** 20판 도중에 이 문장들을
고쳐도 앞 기록이 무효가 되지 않는다. `eventIntervalMs` 비교에 영향이 없다.

11절의 점수표는 하나도 없어지지 않는다. 위에 한 겹 씌우는 것이다.

### 15.2 근무 시계

근무 1초를 1분으로 읽는다. 30초 근무가 30분 당직이 된다.

- 시작은 **02:47**로 고정한다. 가장 이른 사내 공지 시각이다
- 끝은 `totalTimeMs - timeLeftMs`로 정한다. 라이프가 떨어져 중간에 끝나면
  끝 시각도 앞당겨진다
- 통화 시각은 `PHONE.slotMs`(21초)에서 나오므로 **03:08**이다

메모 시각 02:47~03:12가 전부 이 시간대 안에 들어온다.

### 15.3 문단 구성

| 문단 | 내용 |
|---|---|
| 검토 | 올라온 경보 수, 미판정 수, 통과시킨 위협과 막은 정상 |
| 통화 | 상사가 무엇을 지시했고 따랐는지, 무엇이 그것을 뒤집었는지 |
| 마무리 | 중간 교대 여부와 인계 항목 한 건 |

통화 문단은 전화가 걸려 온 판에만 나온다. 못 받은 판은 지시 내용을 적지
않는다 — **받지 않았으면 무슨 말이었는지 모르는 것이 맞다.**

가르는 값은 `phoneAnswered`다. `phoneMissed`만 보면 안 된다. `나중에`로
내린 채 근무가 끝나면(라이프 소진 등) 벨이 끝나지 않아 놓친 것으로도
세어지지 않는데, 그때도 들은 적은 없다. 14.8의 판정 기록과 같은 규칙이다.

지목한 경보가 티어 3 구간에서 끝내 안 뽑힌 판은 그렇게 적는다(14.8).

### 15.4 인계 항목은 하나만

틀린 것 전부를 나열하지 않는다. 판정 기록(SHIFT LOG)이 이미 전부 보여주고
있고, 인수인계서는 **다음 사람이 아침에 처음 할 일**을 적는 자리다.

고르는 순서는 심각도가 먼저, 같으면 판정 종류다.

> `MISSED_THREAT` > `FALSE_POSITIVE` > `TIMEOUT`

미판정은 검토 문단에서 이미 건수로 셌다. 같은 CRITICAL이라면 **잘못 판단한
것**이 손도 못 댄 것보다 앞이다. 통과시킨 위협이 제일 위인 이유는 그것만
아침까지 살아 있기 때문이다.

틀린 것이 하나도 없으면 `특이사항 없습니다.`로 끝난다.

### 15.5 말투

사무적인 존댓말에 사람 말투를 섞는다. "손도 못 댔습니다", "멀쩡한 걸
막았습니다", "더 버티지 못하고 교대했습니다".

**실패가 `GAME OVER`가 아니라 내일 아침 누가 읽을 문장이 되는 것**이 이
장치의 전부다.

### 15.6 경보를 부르는 이름

카드 제목은 영문 대문자라 문장에 넣을 수 없다. 경보 15종마다 사람이 부르는
이름을 따로 둔다(`ALERT_LABELS`).

티어 3 다섯 개는 **상사의 대사와 같은 말로 부른다.** 통화 문단과 인계
문단이 같은 건을 다르게 부르면 읽는 사람이 헷갈린다.

`handover.test.ts`가 15종 전부 이름을 갖는지 검사한다.
