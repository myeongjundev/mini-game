# QA CHECKLIST — SOC SHIFT:30

과제의 숨은 검사 범주를 **구현 전에** 설계해 둔 문서다.
실행 전에 `기대`를 먼저 확정하고, 실행 후 `실제`와 `수정`을 채운다.
결과는 `mini-game/notes/03-test-matrix.md`에도 반영하며, 제출 증거는 `notes/` 쪽을 원본으로 쓴다.

검사 환경: 데스크톱 브라우저, 콘솔 열어둔 상태.

1.15는 게임이 성립하는지 보는 검사다. 가만히 있어도 지지 않으면 미판정 처리가 동작하지 않는 것이다.

### 자동으로 처리한 것과 남은 것

**11.14 · 11.14b · 11.14c · 11.15는 배포본에서 자동으로 확인했습니다.**
자리·겹침·비활성·모션은 게임 루프 없이도 잴 수 있습니다.

**나머지 15개는 여전히 사람이 봐야 합니다.** 자동화 브라우저는 화면을
합성하지 않아 `requestAnimationFrame`이 돌지 않고, 그래서 30초 시계와
경보 제한시간이 흐르지 않습니다. 메모는 경과 3초부터 뜨므로 아예 등장하지
않습니다.

다만 **판정 로직 자체는 단위 검사로 덮여 있습니다.** `App.test.ts`가 메모
중 판정 차단(11.3), 닫은 뒤 판정 복구(11.5), 읽음 문턱(11.9·11.10),
재시작 초기화(11.12)를 확인하고, `memoQueue.test.ts`가 슬롯 시각과 티어
짝짓기(11.1·11.2)를 확인합니다. **사람이 볼 것은 "코드가 맞는가"가 아니라
"손으로 해보면 어떤가"입니다.** 특히 11.4와 11.13입니다.

11.21은 11.13을 대신하는 검사다. 메모를 다시 볼 수 있게 한 뒤로는
"기억나는가"가 아니라 "확인해서 쓸 수 있는가"를 본다. 규칙은
`GAME_SPEC.md` 13.6-1에 있다.

11.13은 이 기능을 넣은 이유 자체다. 방해가 순수한 비용이면 짜증만 남는다.
읽은 뒤 연결 경보를 만났을 때 "아, 아까 그거"가 되어야 한다.
