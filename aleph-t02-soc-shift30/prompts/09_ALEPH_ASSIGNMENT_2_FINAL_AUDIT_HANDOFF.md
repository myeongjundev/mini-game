> 이 문서를 Claude Code에 그대로 전달한다. 이 작업의 목적은 **현재 저장소와
> 최신 공개본을 실제로 검사하고**, 과제 2의 빠진 구현·검증·증거를 보완해

> 적혀 있다는 이유만으로 통과 처리하지 않는다.

## 1. 역할

당신은 브라우저 게임의 구현, QA, 배포 검증, 제출 증거 정리를 함께 책임지는
전문 게임 개발자다. `SOC SHIFT:30`의 기존 규칙과 분위기를 보존하면서 과제의
필수 조건을 증거로 입증한다. 추측한 결과, 실행하지 않은 검사, 새로 만들지
않은 캡처를 완료로 기록하지 않는다.

## 4. 판정 규칙

각 요구사항의 판정은 아래 네 가지 중 하나만 사용한다.

- `통과`: 현재 결과를 직접 검사했고 구체적인 증거가 있다.
- `미통과`: 직접 검사했으며 요구 조건을 만족하지 않는다.
- `증거 부족`: 구현됐을 가능성은 있지만 현재 결과를 입증할 증거가 없다.
- `해당 없음`: 과제 조건상 적용되지 않으며 이유를 적을 수 있다.

모든 항목을 다음 열로 정리한 요구사항 매트릭스를 만든다.

| 요구사항 | 필요한 증거 | 관찰한 증거 | 판정 | 부족한 점 | 다음 행동 |
|---|---|---|---|---|---|

자동 테스트는 로직 증거이고, 화면 캡처나 실제 브라우저 조작을 요구하는 항목의
대체물이 아니다. 직접 수행할 수 없는 검사는 `증거 부족`으로 남기고 사용자가
해야 할 정확한 행동을 한 줄로 적는다.

## 5. 완주 요구사항과 통과 기준

### A. 한 판의 완결성과 상태 표시

- 공개 주소에서 한 판을 시작하고 성공 또는 실패로 끝낸 뒤 다시 시작할 수 있다.
- 시작 후 30초 안에 성공 또는 실패 상태에 도달한다.
- 핵심 조작, 현재 상태, 성공, 실패가 화면에서 명확히 구분된다.
- 성공·실패 뒤 다시 시작하면 시간, 라이프, 점수, 콤보, 현재 경보 등 이전 판
  값이 남지 않는다.
- 로컬 증거에는 시작, 플레이, 성공 또는 실패, 다시 시작 화면이 포함된다.
- 핵심 규칙 문서가 현재 동작과 일치한다.

### B. 입력과 반응형 화면

- 1366×768과 1920×1080에서 조작 영역이 잘리지 않고 가로 넘침이 없다.
- 두 해상도의 로컬 화면 파일과 PC 검사표가 있다.
- 연속 입력, 키 누르고 있기, 같은 경보에 반대 키 연속 입력이 중복 판정을
  만들지 않는다.
- 키보드와 마우스로 핵심 조작을 수행할 수 있다.
- 가로 넘침은 두 해상도에서 아래 값이 `0`인지 기록한다.

```js
document.documentElement.scrollWidth - document.documentElement.clientWidth
```

### C. 포커스·일시정지·장시간 안정성

- 포커스가 이탈하면 시간이 불공정하게 흐르지 않고 상태가 건너뛰지 않는다.
- 복귀 후 자동으로 몰아서 진행되지 않으며 의도한 방식으로 재개된다.
- 수동 일시정지와 재개가 작동하고 중복 타이머를 만들지 않는다.
- 10분 동안 실행한 뒤에도 게임이 정상이며 콘솔 빨간 오류가 0건이다.
- 로드, 플레이, 재시작 뒤의 콘솔도 각각 빨간 오류 0건인지 확인한다.
- 10분 실행 기록과 콘솔 0건 확인 기록을 보관한다.

### D. 난이도 실험

- 변경 전 10회와 변경 후 10회의 실제 플레이 기록이 모두 있다.
- 두 묶음 사이에서 바꾼 난이도 값은 정확히 하나뿐이다.
- 현재 계획상 유일한 변경값은 `eventIntervalMs`, 기준 3000ms와 비교 2000ms다.
- `records/playtest-before.csv`와 `records/playtest-after.csv`의 빈 칸을 추측이나
  자동 생성값으로 채우지 않는다. 각 판 결과 화면에서 실제 값을 옮긴다.
- 20판 동안 브라우저, 1920×1080, 키보드, 음소거 ON, 움직임 줄이기 OFF,
  데이터셋과 다른 난이도 상수를 고정한다.
- 각 판의 성공 여부, 점수, 생존 시간, 검토 수, 정확도, 오탐, 미탐, 미판정,
  최대 콤보, 실패 원인을 기록한다.
- 두 묶음의 범위·중앙값 또는 반복된 실패 원인을 비교하고 최종값 선택 이유를
  그 결과에 연결한다.
- 20판 도중 규칙 결함을 고치거나 다른 난이도 값을 바꾸면 기존 기록이 유효한지
  다시 판단하고, 무효라면 숨기지 말고 재실험한다.

### E. 초기화·저장·손상 복구

- 새 게임에서 현재 판 값은 초기화된다.
- 보존 대상으로 정한 최고 점수와 접근성 설정은 다시 접속해도 유지된다.
- 현재 판의 진행 상태는 보존하지 않는다.
- 저장값 없음, 빈 문자열, 잘못된 JSON, 누락 필드, 잘못된 자료형, 범위 밖 숫자,
  버전 불일치에서도 게임이 중단되지 않고 기본값으로 시작한다.
- 초기화 값과 보존 값 목록, 정상·빈 값·손상 값 검사와 복구 결과를 남긴다.
- 과거 문서 기록만 인용하지 말고 현재 코드와 테스트 및 필요한 브라우저 검사로
  다시 확인한다.

### F. 효과와 접근성 선택권

- 소리와 화면 효과는 정해진 사건이 발생할 때만 실행된다.
- 음소거를 켜면 즉시 소리가 멈춘다.
- 움직임 줄이기를 켜면 즉시 흔들림·과한 움직임이 줄거나 멈춘다.
- 효과를 줄여도 핵심 판정과 성공·실패 규칙은 그대로 작동한다.
- 효과 작동 화면과 음소거 또는 움직임 감소 적용 결과를 증거로 남긴다.

### G. 공개 안전

- 공개 화면, 배포 파일, 제출 문구, 캡처, 문서에 개인정보와 비밀값이 0건이다.
- 실제 비밀값을 출력하지 말고 발견 위치와 조치 종류만 기록한다.
- 공개 주소를 로그인된 관리 화면이 아닌 직접 접속으로 검사한다.
- 공개 페이지, 필수 자산, 새로고침, 네트워크와 콘솔을 현재 배포본에서 확인한다.

### H. 최종 제출물

제출 화면에는 다음 두 종류만 남긴다.

1. 검증 안내서 1개
2. AI 사용 기록 정확히 3줄

증거 캡처, 20회 기록표, 검사표는 비공개 확인 자료로 보관하며 제출 화면의
본문을 불필요하게 늘리지 않는다.

## 6. 평가 카드 5장 — 세부 실행 기준

아래 내용은 제출 화면에 제시된 평가 카드의 기준이다. 앞 절의 체크리스트와
중복되어도 삭제하지 말고, 요구사항 매트릭스에서 대응 항목과 증거를 연결한다.

### 카드 1 — 30초 안에 이해되는 핵심 규칙

**하는 일**

시작, 플레이, 성공 또는 실패, 다시 시작이 이어지는 짧은 게임 한 판을 만든다.

**첫 행동**

- “플레이어는 `[핵심 대상]`을 `[핵심 조작]`하면 성공하고, `[실패 조건]`이
  되면 실패한다”를 현재 게임에 맞는 한 문장으로 채운다.
- 키보드나 마우스 중 핵심 조작 하나를 고르고, 도형과 글자만으로도 한 판이
  끝까지 실행되게 만든다.

**통과 기준**

- 공개 화면에서 시작할 수 있다.
- 조작 뒤 현재 상태가 성공·실패·진행 중 가운데 하나로 구분된다.
- 다시 시작하면 현재 판의 상태가 초기화된다.

**막히는 지점과 확인 순서**

- 무엇부터 만들지 정하기 어렵다면 `플레이어 행동 1개 → 성공 조건 1개 →
  실패 조건 1개`를 먼저 연결한다.
- 조작이나 다시 시작이 반응하지 않으면 `입력 대상의 포커스 → 입력 함수의
  중복 횟수 → 새 판에서 상태·타이머 초기화` 순으로 확인한다.

**남길 것**

- 공개 주소에서 시작할 수 있고, 조작 뒤 현재 상태가 성공·실패·진행 중
  가운데 하나로 구분되는 증거
- 다시 시작하면 현재 판의 상태가 초기화되는 증거

### 카드 2 — PC 숨은 검사

**하는 일**

연속 입력, 창 크기 변경, 포커스 이탈·복귀, 일시정지·재개, 10분 실행에서도
게임이 안정적으로 이어지게 만든다.

**첫 행동**

- 검사 조건, 예상 결과, 실제 결과, 수정 여부 네 칸의 검사표를 만든다.
- 두 기준 해상도와 연속 입력, 포커스 이탈·복귀, 일시정지, 10분 실행을 한
  항목씩 나눠 실행한다.

**통과 기준**

- 조작 영역이 잘리거나 화면 밖으로 넘치지 않는다.
- 조작 1회가 결과 1회로만 반영된다.

**막히는 지점과 확인 순서**

- 창 크기를 바꾸면 문제가 사라질 때는 `게임 영역 실제 크기 → 물체 좌표가
  영역 안인지 → 크기 변경 뒤 좌표 재계산` 순으로 확인한다.
- 복귀 직후 실패하거나 입력이 중복될 때는 `이탈 중 타이머 정지 → 재개 기준
  시각 → 새 판마다 입력 함수가 중복 등록되는지` 순으로 확인한다.

**남길 것**

- 공개 주소 확인 결과
- 조작 영역이 잘리거나 화면 밖으로 넘치지 않고 조작 1회가 결과 1회로
  반영되는 증거

### 카드 3 — 감이 아니라 플레이 데이터로 조정

**하는 일**

플레이 기록을 모아 난이도에 영향을 주는 값 하나를 조정하고 최종값을 정한다.

**첫 행동**

- 생존 시간, 목표 달성 횟수처럼 측정값 1~2개와 실패 원인 분류를 정하고 현재
  설정으로 10회를 기록한다.
- 속도, 등장 간격, 제한 시간 중 하나만 바꿔 같은 조건으로 10회를 다시 기록한다.

현재 프로젝트에서는 이미 `eventIntervalMs` 하나와 두 설정 3000ms·2000ms를
실험 대상으로 정했으므로, 새 변수를 임의로 추가하지 않는다.

**통과 기준**

- 현재 난이도 규칙과 선택한 값이 공개 화면에 보인다.

**막히는 지점과 확인 순서**

- 전·후 결과가 거의 같으면 `측정값이 변화에 민감한지 → 난이도 값 차이 →
  같은 조건으로 다시 기록했는지` 순으로 확인한다.
- 여러 값을 함께 바꿨다면 `변경 전 설정 복원 → 확인할 값 하나 선택 → 나머지
  값 고정 → 10회 재실행` 순으로 바로잡는다.

**남길 것**

- 공개 주소에서 현재 난이도 규칙과 선택한 값이 화면에 보이는 증거
- 전·후 각 10회 원자료와 최종값 선택 근거

### 카드 4 — 저장과 복구

**하는 일**

현재 판의 값은 새 판에서 초기화하고, 보존하기로 한 개인 기록만 다시 접속해도
유지되게 만든다.

**첫 행동**

- 새 판에서 초기화할 값과 다시 접속해도 보존할 값을 나눠 적고 저장값이 없을
  때의 기본값을 정한다.
- 정상값, 빈 값, 글자가 있는 값, 필수 항목이 빠진 값으로 저장 상태를 각각
  바꿔 실행한다.

**통과 기준**

- 새 게임을 시작하면 현재 판 값은 초기화된다.
- 보존하기로 한 기록은 화면에 남는다.

**막히는 지점과 확인 순서**

- 새로 고치면 보존 기록이 사라질 때는 `저장 동작 실행 확인 → 저장된 문자열
  확인 → 불러온 값을 화면에 반영하는지` 순으로 확인한다.
- 손상된 값에서 멈추거나 이전 판이 남을 때는 `값 존재·형식 검사 → 잘못된 값의
  기본값 처리 → 상태·화면·타이머 동시 초기화` 순으로 확인한다.

**남길 것**

- 공개 주소에서 새 게임의 현재 판 값이 초기화되는 증거
- 보존하기로 한 기록이 화면에 남는 증거

### 카드 5 — 손맛과 선택권

**하는 일**

게임의 중요한 사건을 알아차릴 수 있는 효과 하나와 그 효과를 줄이거나 끄는
선택권을 함께 만든다.

**첫 행동**

- 성공, 실패, 충돌, 목표 달성 중 효과가 필요한 사건 하나를 고르고 효과음,
  화면 흔들림, 시각 효과 중 하나를 연결한다.
- 소리가 있으면 음소거, 큰 움직임이 있으면 움직임 감소 선택을 화면에 둔다.

**통과 기준**

- 정한 사건에서만 효과가 보인다.
- 음소거 또는 움직임 줄이기를 누르면 효과가 즉시 줄거나 멈춘다.

**막히는 지점과 확인 순서**

- 효과가 계속 반복되면 `사건 조건이 한 번만 성립하는지 → 상태 변경 뒤 재실행
  여부 → 효과 종료 시점` 순으로 확인한다.
- 끄기 선택이 일부 효과에 적용되지 않으면 `효과 생성 위치 목록 → 공통 설정값
  참조 확인 → 설정 변경 직후 실행 중 효과도 멈추는지` 순으로 확인한다.

**남길 것**

- 공개 주소에서 정한 사건에만 효과가 실행되는 증거
- 음소거 또는 움직임 줄이기를 누르면 효과가 즉시 줄거나 멈추는 증거

## 7. 검증 안내서 작성 계약

반드시 아래 네 제목을 모두 사용한다.

### 어디로 가나요

최신 공개 주소를 한 줄로 적는다.

### 무엇을 하나요

공개 주소에서 바로 실행할 수 있는 행동을 **최대 3단계**로 쓴다. 현재
`notes/06-submission-plan.md` 초안은 5단계이므로 그대로 제출하면 안 된다.
30초 안에 판정 가능한 가장 짧은 경로로 다시 작성한다.

### 무엇이 보이면 통과인가요

시작, 판정에 따른 상태 변화, 성공 또는 실패, 다시 시작 초기화가 눈으로
구분되는 조건을 짧게 쓴다.

### 안 될 때

강력 새로고침, 화면 클릭으로 포커스 복구, 탭 복귀 후 재개, 다른 최신
브라우저 사용 등 실제 문제 해결 방법만 적는다.

오너가 공개 주소의 현재 결과를 15초 안에 판단할 수 있을 정도로 간결하게
작성한다.

## 8. AI 사용 기록 3줄 계약

정확히 세 줄이며 각 줄은 비어 있지 않은 한 문장이어야 한다.

1. AI에게 맡긴 일
2. AI 결과 중 실제로 활용한 일
3. 사용자가 직접 판단·확인·수정했거나 AI 제안을 따르지 않은 일

사용자가 실제로 하지 않은 플레이 검사나 판단을 사용자가 했다고 쓰지 않는다.
현재 `notes/06-submission-plan.md`는 여러 문장을 한 줄에 넣은 초안이므로 실제
작업 기록과 대조해 한 문장씩 다시 확정한다.

## 9. 증거 파일

- 비공개 원본 위치: `C:\gov\SKT-ALEPH\mini-game\evidence`
- 플레이 기록: `C:\gov\SKT-ALEPH\mini-game\records`
- 검사·설계 기록: `C:\gov\SKT-ALEPH\mini-game\notes`
- 파일명과 캡처 절차는 `notes/07-evidence-plan.md`를 따르되 현재 요구사항과
  맞지 않는 부분은 문서도 함께 고친다.
- 캡처에는 계정 정보, 다른 탭, 북마크, 사용자 경로, 토큰이 보이지 않게 한다.
- 최종 확인 PDF를 만들 경우 현재 결과만 사용하고 모든 페이지를 열어 글자 깨짐,
  잘림, 오래된 캡처, 개인정보를 검사한다.

최종 확인 PDF에는 근거가 있는 절만 넣는다.

1. 과제명, 결과 URL, 날짜, 제출 준비 상태
2. 3단계 이내 검증 안내서
3. 제출 문구와 정확히 같은 AI 3줄
4. 모든 요구사항의 판정과 증거
5. 전·후 기록, 콘솔, 입력, 해상도 등 필요한 검사 결과
6. 현재 실행 캡처
7. URL·선택 파일·개인정보/비밀값 최종 교차 확인

## 10. 작업 순서

1. 저장소와 배포본의 현재 상태를 조사하고 요구사항 매트릭스를 작성한다.
2. `미통과`와 `증거 부족`을 구현 결함, 재검사 필요, 사용자 직접 수행 필요로
   나눈다.
3. 과제 범위 안의 구현 결함은 가장 작은 변경으로 고치고 관련 테스트를 추가한다.
4. build, lint, test와 실제 브라우저 검사를 다시 수행한다.
5. 두 해상도, 입력, 포커스, 일시정지, 10분 실행, 콘솔, 저장 복구, 효과 선택,
   개인정보를 검증하고 증거를 정리한다.
6. 실제 20판 기록이 없다면 완료로 꾸미지 말고 사용자 수행 항목으로 명확히
   남긴다. 직접 수행할 수 있다면 계획의 통제 조건을 지켜 전부 기록한다.
7. 3단계 검증 안내서와 사실에 맞는 AI 3줄을 작성한다.
8. 제출 준비 상태를 판정하되 사용자의 별도 허가 없이 과제 제출 버튼을 누르지 않는다.

빠졌거나 실패하면 `제출 불가`다.

## 12. 금지 사항

- 실행하지 않은 검사를 `통과`로 기록하지 않는다.
- 빈 CSV를 임의의 수치로 채우지 않는다.
- 과거 커밋의 결과를 최신 배포본 결과처럼 쓰지 않는다.
- 난이도 실험 도중 둘 이상의 규칙·상수를 바꾸지 않는다.
- 개인정보, 비밀번호, 토큰, API 키를 문서나 출력에 노출하지 않는다.
- 사용자의 미커밋 변경을 삭제하거나 강제로 되돌리지 않는다.
- 백엔드, 로그인, 외부 API 등 과제 밖 기능을 추가하지 않는다.
- 사용자의 명시적 허가 없이 최종 제출하지 않는다.
