실제 실행 전 `예상 결과`를 먼저 작성하고, 실행 후 `실제 결과`와 `수정 여부`를 기록합니다.

이 표가 제출 증거의 원본입니다. 항목별 상세 절차와 확인 방법은 `aleph-t02-soc-shift30/docs/QA_CHECKLIST.md`에 있습니다.

## 검사 환경과 한계

## 저장과 복구 (QA 8절 / STORAGE_AND_RECOVERY 5절)

`loadSaved`에 값을 직접 넣어 16가지를 확인했습니다. **예외 0건, 전부 기대대로.**

| # | 심은 값 | 기대 | 실제 |
|---|---|---|---|
| 1 | (없음) | 기본값 | 통과 |
| 2 | `` (빈 문자열) | 기본값 | 통과 |
| 3 | `abc` | 기본값 | 통과 |
| 4 | `{"bestScore":` | 기본값 | 통과 |
| 5 | `{}` | 기본값 | 통과 |
| 6 | `{"v":1,"bestScore":"높음"}` | 해당 항목만 기본값 | 통과 |
| 7 | `{"v":1,"bestScore":-5}` | 기본값 | 통과 |
| 8 | `{"v":1,"bestScore":2140,...}` | 2140 보존 | 통과 |
| 경계 | `{"v":2,"bestScore":9999}` | 버전 불일치 → 기본값 | 통과 |
| 경계 | `{"v":1,"bestScore":1e999}` | 무한대 → 0 | 통과 |
| 경계 | `[1,2,3]` | 객체 아님 → 기본값 | 통과 |
| 경계 | `null` | 객체 아님 → 기본값 | 통과 |
| 경계 | `{"v":1,"bestScore":1000000}` | 상한 초과 → 0 | 통과 |
| 경계 | `{"v":1,"bestScore":12.5}` | 정수 아님 → 0 | 통과 |
| 경계 | 저장소 읽기 차단 | 예외 삼키고 기본값 | 통과 |
| 경계 | 저장소 쓰기 차단 | 예외 삼키고 진행 | 통과 |

**끝까지 확인 (QA 8.3):** `{"v":1,"bestScore":` 를 실제로 심고 새로고침한
뒤에도 로비가 정상으로 뜨고, SHIFT RECORD의 LOCAL BEST가 `0`,
SOUND가 `OFF`(기본값 `mute: true`)였습니다. 콘솔 오류 0건.

### 9.4가 검사표와 어긋납니다

`.gitignore`는 `evidence/`만 제외하고 있고, **`notes/`와 `records/`는 공개
저장소에 그대로 올라가 있습니다.** 지금까지의 작업 방식(작업 기록을
`notes/`에 커밋)과 검사표의 기대가 서로 다릅니다.

둘 중 하나를 정해야 합니다.

- 검사표를 고친다 — 과제 기록을 공개하는 것이 포트폴리오에 유리하다고
  판단했다면. 저장소를 public으로 바꾼 결정과 같은 논리입니다.
- `.gitignore`를 고친다 — 제출 전까지 비공개로 두려면. 이미 올라간 이력은
  남으므로 새로 올리지 않는 것 이상의 의미는 없습니다.

**공개 저장소이므로 `notes/`와 `records/`에 개인정보를 넣지 않도록
주의해야 합니다.** 현재 내용에서는 발견된 것이 없습니다.
